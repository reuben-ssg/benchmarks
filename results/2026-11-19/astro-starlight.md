# Reuben vs Astro vs Starlight: build-speed benchmark

Run on 2026-11-19. All numbers are wall-clock time of one `build` CLI invocation (process start to exit), measured with hyperfine.

## Headline (warm median, ms; ratio = tool time / Reuben time)

| Set | Reuben | Astro (plain) | ratio | Starlight (default, Pagefind on) | ratio | Starlight (Pagefind off) | ratio |
|---|---|---|---|---|---|---|---|
| Small (4 pages) | 61 | 626 | 10.2x | 911 | 14.9x | 902 | 14.7x |
| Medium (20 pages) | 8.4 | 630 | 75x | 942 | 113x | 901 | 108x |
| Large (1,000 pages) | 321 | 1,036 | 3.2x | 3,992 | 12.4x | 3,558 | 11.1x |

Reuben is faster in every case, but the gap depends heavily on size.
The small and medium ratios are dominated by Astro's fixed startup cost (about 0.6 s of Node, Vite and content-layer start-up even for 4 pages), not by per-page work.
The large (1,000-page) case is the most meaningful for per-page throughput: 3.2x against plain Astro, about 11 to 12x against Starlight.
Reuben's own in-memory Criterion benchmark is not comparable to these numbers: these include process start, config load, writing files and the checks.

## Machine and environment

- Apple M3 Pro, 12 cores (6 performance + 6 efficiency), 18 GiB RAM (19,327,352,832 bytes), macOS 27.2.1 (Darwin 27.2.0), APFS SSD.
- The machine was in normal use throughout (other apps and a Claude Code session open; load average around 4 at the end of the run).
  Nothing was closed. Expect some noise; stddevs are in the table below and are small relative to the gaps.
- Node v26.13.1, npm 11.20.0, hyperfine 2.0.0.
- Reuben 0.1.1, release binary from the npm package `@reuben-ssg/reuben` (real binary: `~/git/reuben-ssg/docs/.worktrees/scaffold/node_modules/@reuben-ssg/reuben/node_modules/.bin_real/reuben`, Mach-O arm64).
- Astro 7.4.11 (`astro@7`), Starlight 0.42.10 (`@astrojs/starlight@latest` resolved under the 7-day minimum release age; 0.43.1 is the dist-tag latest but was not installable under the age rule, so npm picked 0.42.10), Pagefind 1.6.0 (Starlight's dependency).
  The ~/.npmrc release-age settings were left untouched.
  `ignore-scripts=true` from ~/.npmrc was active, so no install scripts ran.

## Method

- Tool: `hyperfine -N` (no shell), 1 warm-up run then 10 measured runs per case, `--prepare` deletes `dist` before every run (including the warm-up).
  Reported: median, mean ± stddev, min, max of the 10 measured runs.
- "Warm": Astro's caches (`.astro`, `node_modules/.vite`, `node_modules/.astro`) are kept between runs; only `dist` is removed.
- "Cold": a single run immediately after deleting `dist`, `.astro`, `node_modules/.vite` and `node_modules/.astro` (Reuben: `dist` only; it has no cache).
  The OS file cache was not purged, so "cold" means no tool caches, not a cold disk.
  One sample each, so cold numbers are anecdotal.
- Each case is a self-contained project directory with its own copy of `node_modules` (APFS clone of the one install).
  Starlight failed to build when its `node_modules` sat outside the project root (a Vite externalisation problem), so this layout was used for both Astro setups.
- Content sets are shared plain Markdown (front matter title and description, headings, lists, code blocks, links), copied into each tool's content folder:
  - Small: the Reuben docs pages `quickstart`, `configuration`, `theming` (unmodified, they contain `{{ }}` only as inline/code-block examples) plus a hand-written plain-Markdown home page (the Rhai/HTML hero removed). 4 pages. The real docs site has a fifth page (`why.md`) and was run as-is only for reference ("docs-asis").
  - Medium: the 28 Markdown files of Nick's personal site (`website/.worktrees/reuben-port/content`), minus the résumé (needs a Rhai sidecar), minus 8 pages with `draft: true` (Reuben skips drafts; Astro would not), leaving 20 pages (index, 404, writing guide, portfolio).
    Reuben's `@/path.md` internal links were rewritten to plain `/path/` links, and links whose target is absent from the set (résumé, drafts, stale refs) were turned into plain text, because Reuben's link resolver otherwise errors and Astro would emit literal `@/…` hrefs.
  - Large: 1,000 pages generated by `scripts/gen.mjs` to match `reuben-core`'s `testsite::generate` (4 collections `guides`/`notes`/`posts`/`refs`, `p00000`..`p00999`, 3 to 5 `##` sections with emphasis and a link to the collection root, inline math, a footnote, a Rust code block, a 2-column table, ~700 KB of Markdown in total).
    Rhai pieces (`card()` include, `data.info.name`, `page.params.section`) were replaced by the equivalent literal HTML/text, so all tools see identical Markdown.
    I added a `description` front-matter field (Reuben's own benchmark has only `title` and `weight`).
- Reuben setup: `reuben.toml` with only `title` and `base_url`; no theme folder, so the built-in theme. Build: `reuben build --root <dir>`.
- Plain Astro setup: `output: 'static'`, content collection with the `glob` loader, one catch-all route `src/pages/[...slug].astro` rendering `render(entry)` inside a minimal layout (title, `<main>`, no client JS).
  No integrations, so no sitemap.
- Starlight setup: default config (`title` only), `docsLoader`/`docsSchema`. The "Pagefind off" variant sets `pagefind: false`, which Starlight supports.
  Starlight's default sidebar autogenerates every page into every page.
- Reproduce: `scripts/gen.mjs`, `scripts/setup.sh`, `scripts/run.sh`, `scripts/summarize.mjs` in this folder.

Pagefind adds about 0.68 MB (small), 0.74 MB (medium) and 4.7 MB (large) of index files plus about 460 KB of JS/WASM glue (the 6 extra JS files).
Starlight's large output is about 155 MB because the autogenerated sidebar listing all 1,000 pages is inlined in every page (about 155 KB per HTML file).
Plain Astro and Reuben ship zero JavaScript. Starlight ships 108 KB (7 files) without Pagefind, 568 KB (13 files) with it.
Reuben's output is a little larger than plain Astro's here (built-in theme CSS and extra markup such as math/highlighting spans, plus a sitemap); the layouts are not equal, so do not read the size gap as a Markdown-rendering difference.

## Feature asymmetries (what each build is doing)

- Reuben runs accessibility checks and link/reference checks during every `build` and has no switch to turn them off.
  On the large set it prints 7,998 accessibility warnings (link text "link" does not say where it goes, etc.) to stderr per build; that cost is included in the Reuben timings.
  So Reuben's numbers include work Astro does not do. I could not time Reuben without checks.
- Reuben renders syntax highlighting, math (MathML) and footnotes natively. Astro (Shiki highlighting, GFM footnotes) does not render the `$...$` math by default, so the large set's inline math is literal text in the Astro outputs.
- Reuben's per-page output includes the built-in theme and a sitemap; plain Astro here has no theme and no sitemap integration; Starlight has a theme, sidebar, search UI, sitemap and 404 page.
- Starlight adds Pagefind indexing (about +0.4 s on 1,000 pages, +12%; indistinguishable from noise on 4 and 20 pages) and a heavy default theme/sidebar.
- Reuben small (61 ms) is much slower than Reuben medium (8 ms) despite fewer pages.
  The small set is the docs pages, which are full of code blocks; the first syntax highlight apparently carries a fixed start-up cost (about 50 ms) that the medium set, with almost no code blocks, never pays.
  I did not verify this explanation.
- Astro's cost is mostly fixed (about 0.6 s whether 4 or 20 pages); Reuben's is tiny at small sizes, so ratios on small sets say little about large-site behaviour.
- Reuben is a single native binary; Astro runs on Node and was invoked via its own `node_modules/.bin/astro` (no `npx`/npm wrapper overhead). Reuben was invoked through its real binary, not the npm wrapper script.

## Caveats

- One machine, one OS, normal desktop use (not isolated), 10 runs per case. Run-to-run spread was small (<5% for most cases) but background load can bias results.
- Cold runs are single samples and do not purge the OS file cache.
- Starlight 0.42.10, not 0.43.1, because of the 7-day release-age rule; newer releases of either tool may differ.
- The medium set was edited (links, drafts removed, résumé removed) to make it buildable by both tools; the large set's Rhai was replaced with literal text; the small home page is hand-written. Content is identical across tools, but it is not "as authored" for Reuben.
- Plain Astro's layout is deliberately minimal, so its output work is small. A real Astro site with a theme, images or integrations would be slower.
- Reuben is evaluated with its built-in theme only; a custom theme (as on the real docs site, 79 ms vs 61 ms for the comparable small build) adds cost.
- No claim is made about dev-server, incremental rebuild or memory beyond the peak-RSS column.
